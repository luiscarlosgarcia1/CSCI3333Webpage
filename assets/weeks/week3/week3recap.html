CSCI 3333 · Week 03

Sorting Bounds & Bounded Universes

Why comparison sorting has an Ω(N log N) limit, and how integer keys let counting sort and radix sort bypass it.

01 Comparison Sorting: An Upper Bound

Recap

A comparison sort learns order only by asking questions such as a[i] < a[j]. Merge sort and QuickSort show that sorting can be done in O(N log N) comparisons: each level handles N items, and there are about log N levels.

Visual

Merge sort levels for N = 8

8 items       do N total merge work
4 + 4         do N total merge work
2 + 2 + 2 + 2 do N total merge work
1 + ... + 1

log₂ 8 = 3 levels  ×  8 work/level = Θ(N log N)

Core idea

For an upper bound, one successful algorithm is enough. Merge sort guarantees Θ(N log N); QuickSort has expected O(N log N) time when its partitions are reasonably balanced.

Textbook basis: Sections 7.6, “Mergesort,” and 7.7, “Quicksort.”

02 Comparison Sorting: A Lower Bound

Recap

There are N! possible orders for N distinct items. A correct comparison sort must distinguish all of them. Since one comparison has only two outcomes, its decision tree needs at least N! leaves.

Visual · Three items

                 compare a and b
                   /             \
                a < b           b < a
                 ...             ...

Leaves must cover every possible order:
abc  acb  bac  bca  cab  cba

6 leaves require a tree of height at least log₂(6).

Lower-bound result

height ≥ log₂(N!) = Ω(N log N)

So no comparison-based sorting algorithm can guarantee better than Ω(N log N) time in the worst case. Together with merge sort’s upper bound, comparison sorting has a tight Θ(N log N) bound.

Textbook basis: Section 7.8, “A Lower Bound for Sorting.”

03 Counting Sort

Recap

Counting sort applies when keys are integers from a small known range, 0 through K - 1. Instead of comparing values, count how often each key occurs, then emit each key that many times.

Visual

Input:  [ 2, 0, 2, 1, 1, 0 ]
Count:  [ 2, 2, 2 ]
index:    0  1  2

output 0 twice, 1 twice, 2 twice
Result: [ 0, 0, 1, 1, 2, 2 ]

Pseudocode

countingSort(A, K):
    counts = array of K zeros
    for each x in A:
        counts[x] += 1
    for key from 0 to K - 1:
        output key, counts[key] times

The running time is O(N + K). It is linear when the key range K is not much larger than N.

04 Radix Sort

Recap

Radix sort sorts fixed-width integer keys one digit at a time, from least significant to most significant. Each digit pass must use a stable sort, so equal-digit items keep the order established by earlier passes.

Visual · Ones, then tens

Input:        [ 31, 12, 23, 14 ]
ones digit:   [ 31, 12, 23, 14 ]
tens digit:   [ 12, 14, 23, 31 ]

The ones-digit ordering is preserved within
each equal tens-digit group.

Pseudocode

radixSort(A, d):
    for digit from least significant to most significant:
        stably counting-sort A by that digit

With d digits in base K, the time is O(d(N + K)). These sorts evade the comparison lower bound because they inspect key values directly rather than only comparing pairs.

Textbook basis: Section 7.11, “Bucket-Sort and Radix-Sort.”
