Hash Tables, Maps & Graph Search

A compact review of fast key-value lookup, graph representations, and breadth-first search.

01 Graphs

Recap

A graph models relationships: vertices are the items, and edges are the connections. An edge may be undirected, or directed from one vertex to another. An adjacency list stores the neighbors of each vertex and is especially useful when the graph has relatively few edges.

Visual · Directed adjacency list

    A ──→ B
    │     │
    ↓     ↓
    C ──→ D

A: B, C
B: D
C: D
D:

Core idea

For an adjacency-list graph, visiting every vertex and every listed edge takes O(V + E), where V is the number of vertices and E is the number of edges.

Textbook basis: Sections 9.1–9.2.

02 Breadth-First Search

Recap

Breadth-first search (BFS) explores outward from a starting vertex one edge at a time. A queue keeps the earliest discovered vertex ready to process, so the first time BFS reaches a vertex it has used the fewest edges from the start.

Visual · Start at A

graph:  A ─ B ─ D
        │   │
        C ─ E

queue / visit order:
[A] → visit A, add B C
[B, C] → visit B, add D E
[C, D, E] → visit C

levels: A | B C | D E

Pseudocode

BFS(start):
    mark start visited
    enqueue start

    while queue is not empty:
        v = dequeue
        visit v
        for each neighbor w of v:
            if w is unvisited:
                mark w visited
                enqueue w

BFS runs in O(V + E) with an adjacency list.

Textbook basis: Section 9.3.

03 Hash Tables

Recap

A hash table uses a hash function to turn a key into an array position, called a bucket. It is a good fit when the goal is fast lookup by key rather than sorted order. Two different keys can map to the same bucket; that is a collision.

Visual · Separate chaining

table size = 5
h(key) = key mod 5

bucket 0:  10 → 25
bucket 1:
bucket 2:   7
bucket 3:
bucket 4:  14

10 and 25 collide because both hash to 0.

Core idea

With a well-distributed hash function and a controlled load factor, lookup, insertion, and removal are O(1) on average. When too many items share too few buckets, the table is rehashed into a larger table to keep those operations fast.

Textbook basis: Sections 5.1–5.6, “Hashing.”

04 map & unordered_map

Recap

Both containers store unique key-value pairs. Choose std::map when keys must stay sorted; its lookup, insertion, and removal are O(log N). Choose std::unordered_map for average O(1) lookup when key order does not matter.

Example

#include <map>
#include <unordered_map>

std::map<std::string, int> scores;
scores["Ada"] = 95; // keys in sorted order

std::unordered_map<std::string, int> counts;
counts["heap"]++; // key goes to hash bucket

Use the key

if (scores.contains("Ada")):
    score = scores.at("Ada")

for each [name, score] in scores:
    visit pairs by name order

operator[] accesses a key but creates a value when that key is absent. Use at() when a missing key should be reported instead of inserted.

Textbook basis: Chapter 5, “Hashing”; C++ container details: std::map and std::unordered_map.
