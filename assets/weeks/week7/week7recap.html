CSCI 3333 · Week 07

Heaps, Hash Tables & Maps

A compact review of priority queues, binary heaps, hashing, and C++ key-value containers.

01 Priority Queues

Recap

A priority queue stores items with priorities. Unlike a regular queue, the next item removed is the item with the best priority—not necessarily the item that arrived first. A min-priority queue removes the smallest item; a max-priority queue removes the largest.

Visual

min-priority queue
insert:  7, 3, 9, 4
remove:  3 → 4 → 7 → 9
The minimum stays ready at the front.

Core operations

insert(x)       add x
findMin()       inspect the minimum
removeMin()     remove and return the minimum
isEmpty()       test whether no items remain

Binary heap implementation:
insert / removeMin: O(log N)
findMin:            O(1)

Textbook basis: Sections 6.1–6.2, “Model” and “Simple Implementations.”

02 Binary Heaps

Recap

A binary heap is a complete binary tree usually stored in an array. In a min heap, every parent is less than or equal to each child, so the root is the minimum. In a max heap, every parent is greater than or equal to each child, so the root is the maximum. The remaining values are not fully sorted.

Visual · Min-heap array representation

          3       index:  1  2  3  4  5  6
        /   \     heap:  [3, 5, 7, 9, 6, 8]
       5     7
      / \   /
     9   6 8

For index i: 
parent = i / 2
left   = 2i
right  = 2i + 1

Pseudocode · Min heap

insert(x):
    place x in the next open array slot
    while x is smaller than its parent:
        swap x with its parent

removeMin():
    save the root
    move the last item to the root
    repeatedly swap it with its smaller child
    return the saved root

Pseudocode · Max heap

insert(x):
    place x in the next open array slot
    while x is larger than its parent:
        swap x with its parent

removeMax():
    save the root
    move the last item to the root
    repeatedly swap it with its larger child
    return the saved root

Textbook basis: Sections 6.3.1–6.3.3, “Binary Heap.”

03 Hash Tables

Recap

A hash table uses a hash function to turn a key into an array position, called a bucket. It is a good fit when the goal is fast lookup by key rather than sorted order. Two different keys can map to the same bucket; that is a collision.

Visual · Separate chaining

table size = 5
h(key) = key mod 5

bucket 0:  10 → 25
bucket 1:
bucket 2:   7
bucket 3:
bucket 4:  14

10 and 25 collide because both hash to 0.

Core idea

With a well-distributed hash function and a controlled load factor, lookup, insertion, and removal are O(1) on average. When too many items share too few buckets, the table is rehashed into a larger table to keep those operations fast.

Textbook basis: Sections 5.1–5.6, “Hashing.”

04 map & unordered_map

Recap

Both containers store unique key-value pairs. Choose std::map when keys must stay sorted; its lookup, insertion, and removal are O(log N). Choose std::unordered_map for average O(1) lookup when key order does not matter.

Example

#include <map>
#include <unordered_map>

std::map<std::string, int> scores;
scores["Ada"] = 95; // keys in sorted order

std::unordered_map<std::string, int> counts;
counts["heap"]++; // key goes to hash bucket

Use the key

if (scores.contains("Ada")):
    score = scores.at("Ada")

for each [name, score] in scores:
    visit pairs by name order

operator[] accesses a key but creates a value when that key is absent. Use at() when a missing key should be reported instead of inserted.

Textbook basis: Chapter 5, “Hashing”; C++ container details: std::map and std::unordered_map.
